## 一、适用场景

工作归档人员完成一场校园活动后，将活动材料一次性提交给 AI，AI 依据本 Skill 同时交付两份文档：

1. **新闻稿**（对外宣传，正文严格 500 -520 字）
2. **工作总结**（对内归档复盘，结构完整、严禁冗长，严格控制在 800—2000 字）

---

## 二、输入规范：归档人员需要提供什么

归档人员按以下清单提交材料。**必填项缺失时，AI 不得编造，应标注“【待补】”并列出缺失项；选填项缺失时，AI 可先留空标注“【待补】”，不必要写的可不写该部分。**

### 1. 必填信息

用户可以通过传入策划文档、在工作区中提及已有策划来提供基本信息、目的等内容。流程和现场情况需要工作人员说明。

| 类别         | 具体内容                                                                                                                     |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 活动基本信息 | 活动全称、系列名与期数、主题、时间、地点、主办/承办部门、参与人数                                                            |
| 活动目的     | 为什么办、面向谁、希望达到什么效果                                                                                           |
| 活动流程     | 按环节列出：签到、开场、讲解、示范、实践、展示、合影、反馈等                                                                 |
| 现场情况     | 氛围、学生状态、工作人员指导情况、有无互动亮点                                                                               |
| 成果信息     | 作品数量与类型、问卷回收数、满意度、代表性反馈、形成的经验或方法等等                                                         |
| 配图         | 用户可以在工作区提供所有完整图片，由多模态大模型进行筛选和拼图；也可以提供每张图的内容与建议图注（现场全景/过程特写/作品图） |

### 2. 选填信息

| 类别               | 具体内容                                                                  |
| ------------------ | ------------------------------------------------------------------------- |
| 策划分工表         | 负责人+职责，若无，AI 可留“【待补】”                                    |
| 前期筹备细节       | 物料、场地、通知、PPT、音乐等若无，AI 可不写                              |
| 不足与改进         | 若无，AI 可留“【待补】”并提供该部分建议                                 |
| 往期同系列稿件     | 用于统一活动主题和部门等的表述。若无，AI 可根据其他文件推理，或者留下占位 |
| 发布要求           | 字数、格式、发布平台要求。若无，AI 可按照模板执行                         |
| 需要特别说明的表述 | 必须要的表述、不能说明的表述、特殊说明等。若无则不写、不考虑              |

### 3. 输入模板

```text
【活动名称】
【系列/期数】
【时间】【地点】
【主办/承办】
【参与人数】
【活动目的】
【流程环节】1. 2. 3. …
【现场亮点】
【成果数据】作品数：  问卷数：  满意度：  其他：
【代表性反馈】
【策划分工】负责人—职责
【不足与改进】
【宣传禁忌/必写表述】
【配图及图注】
【往期稿件参考】
```

### 4. 缺失处理规则

- **缺时间、地点、人数、成果数据**：标“【待补】”，严禁虚构。
- **缺分工、不足改进**：工作总结中可省略对应小节，新闻稿本就不写。
- **缺现场细节**：用“同学们专注投入、氛围融洽”等概括性表述，不编造具体对话。
- **材料矛盾时**：以归档人员确认版为准，并在交付说明中提示矛盾点。

## 三、处理流程

1. **查阅参考与核对输入**：提取必填项列出缺失清单；结合活动类型查阅 [references/](./references/) 往期范文，统一品牌口径。
2. **先写工作总结（信息母本）**：因为总结信息最全，是新闻稿的素材池；全流程复盘，克制使用表格，过滤单人非共性杂音。
3. **压缩提炼新闻稿**：按 500-520 字硬约束做“删分工、删不足、缩略过程、留成果、升意义”，**对生活与现场负面细节进行公文高阶雅化**。
4. **自动化脚本体检（字数唯一判定依据）**：**AI 严禁凭空心算或主观臆测字数，唯一合法的字数把关依据必须且只能是运行本地脚本 `python3 scripts/word_count.py` 与 `python3 scripts/de-ai-check.py` 的终端真实输出**！若脚本报错或超限，必须以脚本数字为依据持续修改，直到脚本输出通过。
5. **独立子 Agent / 苏格拉底自省审查（价值观与公文审校关口）**：**必须开独立子 Agent（或进入严苛主审视角的苏格拉底追问模式）**，针对“政治站位、新时代文明之风、向上向善、家丑不可外扬、各类型活动敏感肌与公文雅化”进行深度背靠背审校，不通过严禁交付。
6. **智能拼图与 Word 成果交付**：根据段落节奏处理拼图，套用 WordML 模板直接输出排版完成的 `.docx` / `.xml` 成果文件。

## 四、产物1：工作总结（结构完整，严格控制在 800—2000 字）

### 1. 结构模板

1. **活动名称**
2. **活动来源/背景**
3. **策划分工**（负责人—职责）
4. **具体实施**（按环节分点，重点内容，详述活动现场流程）
5. **总结归档**（前期/中期/后期/宣传材料）
6. **活动成果**（量化数据+质性成效）
7. **不足与改进**（问题—措施一一对应）
8. **工作感想/下一步**

### 2. 字数硬性约束（严格控制 800—2000 字，严禁冗长拖沓）

工作总结虽需全流程深度复盘，但**严禁篇幅冗长失控（坚决杜绝废话连篇、大段铺陈）**。必须以 Office Word / WPS 的“字符数（不计空格）”为准，严格控制在 **800—2000 字符**区间（**字数唯一合法依据必须来自本地脚本 `python3 scripts/word_count.py` 的实测输出**）：

- 常规小型活动：Word 字符 **800—1200 字**（精炼完成八大模块，重点写清关键流程与改进实招）；
- 重点复杂活动（含问卷数据与深度反思）：Word 字符 **1300—1800 字**，**上限坚决严禁突破 2000 字符**；
- 材料极少时：不低于 **800 字符**，确保八大部分不缺项。
- **杜绝车轱辘话与表格泛滥**：严禁把问卷原始填空逐条机械照搬，严禁把每个细节展开成长篇大论，务求文字精练、复盘有力。AI 撰写完成后必须运行脚本核验，超 2000 字符必须删减浓缩！

### 3. 注意事项

- **分工必须责任到人**：姓名+事项+具体内容，不能只写“工作人员”。
- **实施过程要可复现**：签到—教学—制作—展示—反馈，每步写清操作方式。
- **成果尽量量化**：参与人数、作品数、问卷回收数、满意人数、愿意再参加人数。
- **不足与改进一一对应**：先问题后措施，措施要具体（如“多备10%—15%材料”“专人调控音乐音量”）。
- **问卷与问题筛选机制（剔除个例杂音）**：问卷反馈不设死板条数限制，但必须建立“共性与个例”的过滤机制。**严禁将仅 1 人提及、偶发、缺乏代表性或合理性的主观抱怨/偏激个例直接立项为改进点**。只有反映出组织缺陷、流程漏洞或具有普遍共性（至少 2~3 人提及或确实涉及规则盲区）的问题，才可提炼为“问题—措施”。
- **克制使用表格（杜绝表格泛滥）**：工作总结正文以**层次清晰的条目化小标题**呈现为主，仅在“策划分工”或“量化成果数据”处使用紧凑小表，**严禁全篇滥用长表格**将实施流程、问题复盘切碎，保证阅读流畅性。
- **归档分类清楚**：前期、中期、后期、宣传四类材料分别列明。
- **不回避问题**：这是总结区别于新闻稿的核心价值。
- **数据与新闻稿一致**：人数、作品数、时间地点不得两稿矛盾。

### 4. 工作总结自检清单

- [ ] 八个部分齐全（或说明省略原因）
- [ ] 分工有姓名、有职责
- [ ] 实施步骤可复现
- [ ] 成果有数据
- [ ] 不足与改进一一对应
- [ ] 归档材料分类列明
- [ ] 与新闻稿数据一致
- [ ] 缺失项已标“【待补】”

## 五、产物2：新闻稿（正文 500-520 字）

### 1. 硬性约束与字数统计权威准绳

> 🚨 **【字数判定的终极铁律：AI 唯一合法参考标准】**
> - **严禁 AI 凭空臆测、心算或依据自身 Token 估算字数**！LLM 在无工具时对长文本的字数感知极不准确，极易出现“口称 506 字，实际 Word 显示 660+”的虚假过关现象。
> - **AI 撰写与交付文稿时，唯一、绝对且排他的字数把关依据，必须且只能是运行本地脚本 `python3 scripts/word_count.py`（或 `de-ai-check.py`）后终端打印的真实统计输出**！
> - **强制闭环流程**：AI 在起草完初稿后，**必须强制执行脚本检测**。如果脚本报告超出 `[480, 540]` 容差区间，AI 必须无条件以脚本报告的实际 Word 字符数为准进行删减压缩，反复迭代直到脚本输出 `✅ 正文字数完美达标` 为止！任何未经过脚本实际测算就宣称“字数已控制在 500-520 字”的交付均属无效交付。

- **统计基准标准：必须以 Microsoft Word / WPS Office 的“字符数（不计空格）”为最终依据**！
  * **大模型的严重认知盲区**：很多 AI 默认只统计纯汉字正则 `[\u4e00-\u9fa5]`，以为自己写了 506 字；但 Office Word / WPS 严格统计所有非空白字符（包括全半角标点符号、数字、英文字母）。一篇公文正文中的时间、地点、数字和标点常占 **50～70 字符**！
  * **撰写换算黄金律**：大模型若想让 Word 选修正文时精准落在 **500—520 字符**，撰写时的**纯汉字数量应瞄准在 440—460 字左右**！预留出标点与数字的字符空间，避免在 Word 里暴涨至 580~600+ 字。
- **正文 Word 字符数严格 500—520 字区间**（硬性容差 480—540 字符）；不含标题、发布信息栏、图注。
- **过程段严格限 1~2 段（占比 <= 30%、防冗长、严禁流水账）**：主体过程只作高度概括（讲解核心要点、示范关键步骤、现场专注实践与互动），**过程段 Word 字符数必须 <= 150 字（正文占比必须在 30% 以内）**，严禁将破冰、发言、讨论、总结逐一分拆成 3~4 个大段铺陈细节。
- 第三人称、正式简洁、积极正面。
- 不写负责人姓名、不写策划分工、不写不足与改进、不写物料采购等内部细节。
- **政治站位与文明之风（向上向善）**：新闻稿是对外展示青年学子风采的官方窗口，必须符合新时代文明之风、弘扬主旋律与正能量，严禁传播低俗、消极、抱怨等负面导向。
- **公文雅化与“家丑不外扬”原则（各类型活动敏感肌防线）**：严禁将现场生活恶习、市井摩擦、私人情感隐私或操作失误直接曝光在新闻稿中，必须做高阶公文抽象与雅化：
  * **人际寝室类**：座谈口角（卫生、作息、噪音摩擦）→ 抽象为“日常作息协调、生活习惯包容互谅、宿舍公区秩序维护”；
  * **恋爱心理类**：私人八卦纠纷、表白受挫、情感纠葛 → 抽象为“树立理性健康的交往观、把握相互尊重的社交边界、提升青年情感沟通能力”；
  * **手工实践类**：制作翻车、材料损坏、工具粗糙等 → 抽象为“在反复调试与动手摸索中体悟传统技艺的精湛严谨”；
  * **体育拓展类**：对抗失误、落后沮丧、体能不支 → 抽象为“弘扬团结协作的体育精神、锤炼坚韧不拔的意志品质”；
  * **学术科创类**：组员分歧、代码报错、项目卡壳 → 抽象为“在攻坚克难中碰撞思维火花、在团队协同中激发创新潜能”。
- **严禁堆砌问卷明细与批评建议**：对外稿只做宏观成效概括（“同学们反响热烈，普遍表示引发强烈共鸣，收获了实用沟通技巧”），严禁出现“回收问卷XX份”、“X人觉得不满意”、“下次想解决XX问题”等对内复盘统计。
- 必须含：标题、导语、过程、成果、意义展望；配图位置用“【配图：…】”标注。

### 2. 结构模板与精细字数分配（对齐 Word 字符数）

| 部分     | Word 字符数（不计空格） | 纯汉字建议 | 正文占比 | 要点                                            |
| -------- | ----------------------: | ---------: | -------: | ----------------------------------------------- |
| 标题     |                20—30 字符 |   18—26 字 |    ——    | 单位+成功举办+第X期品牌名+主题                  |
| 导语     |              110—125 字符 |   80—90 字 |  约 22%  | 目的+时间+地点+主办+活动名+参与对象，末句点价值 |
| **主体过程** |         **135—155 字符** | **115—135 字** | **<= 30%** | **限1~2段！精炼动作，概括环节，杜绝剧本式流水账** |
| 成果展示 |              110—125 字符 |   90—105 字 |  约 22%  | 作品数量/类型/风格概括，或现场反响共鸣          |
| 意义展望 |              120—135 字符 |  100—115 字 |  约 25%  | 能力、文化、交流等成效+未来品牌展望             |
| **正文合计** | **严格 500—520 字符** | **440—460 字** | **100%** | **对齐 Word 状态栏（容差区间 480—540 字符，超 540 字符驳回）** |

### 3. 压缩与归并要点（防过程段冗长的核心法则）

- **并（多环节高度归并，严禁单独提及小环节）**：
  * **核心原则**：**必须用一两句话统领概括许多个小环节，坚决不要逐一单独提及细碎小环节**！
  * **❌ 严重踩雷（逐项流水账报菜名，动辄占300多字）**：先写大风吹破冰定下规则，再分段写第一组聊作息、第二组聊卫生、第三组聊习惯，再写老师讲方法一、方法二……把活动议程当剧本写。
  * **✅ 正确做法（一两句话高效打包归纳，仅需120—150字）**：“活动在轻松热烈的破冰游戏中拉开序幕。随后，同学们围绕共同生活中的沟通协作展开分组研讨与交流，现场氛围融洽；主讲老师结合实际案例进行针对性指导，引导大家掌握换位思考与正向表达的实用方法。”（手工类活动同理：不逐句描写剪裁、上胶、调温，直接概括为“在指导老师示范带领下，同学们专注投入制作，在动手调试中掌握了核心技法”）。
- **删**：分工姓名、物料清单、场地预约、问卷明细、内部不足与改进、过多细碎流程。
- **留**：主讲人核心指导、学生专注状态、成果类型概括、育人品牌价值。
- **升**：把具体成果上升为“增进沟通互谅、锻炼实践能力、增强文化认同”等宏观表述。

### 4. 注意事项

- 标题不宜超过 30 字，避免“活动：主题”重复堆叠。
- 导语五要素齐全，第一句就要让读者知道“谁在哪天办了什么事”。
- 过程段不要写成流水账，用一两句话统领概括多个细碎环节，严格控制在 1~2 个自然段（140—160 字），严禁单独逐一描写小环节。
- 成果段用“部分作品……部分作品……还有的……”的排比概括，不逐件罗列。
- 结尾展望要落到品牌系列或育人体系，不空喊口号。
- 图注简短，标明“现场全景/制作特写/作品展示”。
- 全文避免“我们”，统一用“计算机学院”（或对应主办学院）“同学们”“工作人员”。

### 5. 新闻稿自检清单

- [ ] 正文严格 500—520 字（容差区间 490—540 字）
- [ ] 过程段严格受控在 1~2 段（140—160 字），杜绝多段流水账
- [ ] 标题含单位、期数、主题
- [ ] 导语含目的、时间、地点、主办、活动名、参与对象
- [ ] 成果段有数量或类型概括
- [ ] 结尾有意义升华与未来展望
- [ ] 无负责人姓名、无分工、无内部不足改进
- [ ] 配图位置与图注已标
- [ ] 无虚构数据，缺失项已标“【待补】”

## 七、AI风味自检与 Word 真实字数分块体检（De-AI & Accurate Word Count）

参考 `Humanizer-zh`、`de-AI-writing` 与 `humanizer` 的核心原则，文稿在交付前必须经过“去 AI 味”与“Word 真实字数分块”双重深度体检，彻底剔除大模型常见的浮夸套话、机械结构与字数自欺欺人，确保文稿读起来像经验丰富的学生骨干亲手撰写的真实公文。

技能内置两款开箱即用的自动化体检脚本：

### 1. 自动化体检工具箱与字数唯一依据

> ⚠️ **【特别强调：AI 唯一字数参考准绳】**
> **AI 在撰写、压缩、自检和生成《交付说明》的整个生命周期中，唯一合法的字数参考依据必须且只能是运行本地脚本 `python3 scripts/word_count.py`（或 `de-ai-check.py`）后终端给出的真实输出结果！**
> - 严禁 AI 基于自身内部感觉、Token 数量或纯汉字心算来宣称“字数达标”。
> - 脚本报错未达标（如新闻稿突破 540 字符或过程段超 30%、工作总结超 2000 字符），AI 必须无条件以脚本报告的差额进行重写与精简，直到脚本完全通过为止！

#### ① 独立字数与分块切片统计（对齐 Office Word / WPS 状态栏，支持 .md / .docx）
支持解析 Markdown 与原生 `.docx` 文件，精准输出 Office Word 底层“字符数（不计空格）”，并切片呈现导语、过程、成果、展望各段占比，严格把关过程段 <= 30% 上限：
```bash
python3 scripts/word_count.py <文稿路径.md 或 .docx> --type [news|summary|auto]
```

#### ② 去 AI 味与公文合规体检
扫描大模型高频指纹套话、二分对照壳、虚构拔高词汇，以及对外新闻稿违规出现寝室口角/前任八卦等负面不雅词：
```bash
python3 scripts/de-ai-check.py <文稿路径> --type [news|summary]
```

### 2. 核心校准原则（管所有文风的总规则）

- **实词叙事，克制升华**：新闻稿只在结尾段做合规展望，过程段和成果段只写真实的动手动作（剪裁、弯折、讨论、投票、调温、记录），严禁在中间段落堆砌形容词。
- **事实第一，禁止脑补**：严禁无中生有编造细节。没有具体对话就概括氛围，没有数据就标“【待补】”，严禁编造“99%满意度”、“掌声雷动”等虚构场景。
- **瞄准高校公文真实区间**：既不搞机器假大空（如“谱写时代华章”），也不搞网络口语化，保持客观、规范、务实的高校宣传语境。

### 2. 四层 AI 痕迹拦截清单

#### ① 篇章与结构层（Discourse Level）

- 🚫 **严禁“段段升华”**：AI 极喜欢在每个自然段最后一句强行总结价值（如“让非遗之美落到实处”、“在同学们心间播下了种子”）。**除文末展望段外，所有中间段落严禁段尾喊口号**。
- 🚫 **严禁设问与互动腔**：禁止出现“那么，活动究竟有哪些亮点呢？”、“究竟同学们收获了什么？”等客服式/讲义式自问自答。
- 🚫 **严禁机械“三凑三”**：避免为了对称刻意凑齐三组排比句（如“既锻炼了……又提升了……还增强了……”），根据实际情况写 1~2 个真实落脚点即可。

#### ② 句式与模板壳（Syntax Level）

- 🚫 **清零二分对照壳**：严禁使用“不是……而是……”、“不仅是一次……，更是一场……”、“不仅在于……而在于……”等刻板框架。直接陈述事实，例如将“这不仅是一次简单的掐丝珐琅手工体验，更是一场深刻的中华优秀传统文化洗礼”改为“本次活动以非遗手工艺体验为核心，让同学们在亲手制作中感受传统工艺的精湛与魅力”。
- 🚫 **清零步骤指示过渡句**：严禁使用“把背景介绍完后，活动便进入了……”、“在了解了制作流程之后，接下来就是实践环节”。直接从新动作起笔：“随后，同学们开始动手弯折铜丝、调配釉料”。
- 🚫 **严禁指示性定位壳**：严禁出现“活动的魅力/难点/亮点正在于此”、“最关键的地方在于”。

#### ③ 词汇与修辞黑名单（Vocab Level）

文稿中**绝对禁止**出现以下具有典型大模型指纹的高频词汇：

| 类别                   | 严厉禁止词汇（黑名单）                                                                                       | 正确的改写方向                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| **虚浮拔高词**   | 犹如一场盛宴、饕餮盛宴、画卷徐徐展开、谱写华章、润物细无声、注入灵魂、重头戏、铸就、熠熠生辉、点亮心灯、洗礼 | 改为具体客观动作：“展示了多种风格的作品”、“完成了45件书签制作” |
| **机械路标词**   | 值得注意的是、值得一提的是、毋庸置疑、显而易见、总而言之、综上所述、换句话说、不难发现、毋庸讳言             | 直接删掉，语义用逗号或句号自然顺接                                 |
| **虚假概括套话** | 纷纷表示受益匪浅、引起了强烈反响、获得了一致好评、大家热情高涨、掌声雷动                                     | 改写真实问卷数据（如“多数同学表示学到了新技能”）或具体作品反馈   |
| **违规人称代词** | 我们、我院、我部、我校（对外新闻稿严禁使用）                                                                 | 统一改为第三人称：“计算机学院”、“同学们”、“工作人员”         |

#### ④ 工作总结特有去 AI 味规范

- 🚫 **严禁“假反思”**：AI 写的总结常把不足写成“活动宣传覆盖面仍可进一步扩大”、“未来将进一步提高站位”，毫无实际复盘价值。
- ✅ **必须“硬碰硬”**：不足与改进必须具体到物料损耗比例（如“多备10%—15%备用料”）、场地指引（“提前发布路线图”）、时间调控（“专人把控环节时长”）。

### 3. AI 风味自检执行清单（交付前逐项核对）

- [ ] 中间段落是否已剔除段尾无意义口号升华？
- [ ] 全文是否已清零“不是……而是……”、“不仅是……更是……”等二分对照壳？
- [ ] 是否已清零“值得注意的是”、“显而易见”等大模型路标词？
- [ ] 对外新闻稿是否已杜绝“我们”、“我院”等第一人称？
- [ ] 是否已剔除“饕餮盛宴”、“谱写华章”、“润物细无声”等虚浮形容词？
- [ ] 涉及成效部分是否有具体作品类型或客观数字支撑，杜绝“纷纷表示受益匪浅”？
- [ ] 工作总结的“不足与改进”是否真实具体且一一对应，无避重就轻的空话？

### 4. 独立语义审校规程（苏格拉底子 Agent 追问审查机制）

> ⚠️ **杜绝“规则过拟合”与“假合格”认知底线**：
> 任何脚本工具（如 `de-ai-check.py`）或关键词黑名单（如泡面、刷碗）只能排查字数和低级死板词汇，**极易产生过拟合错觉——脚本通过并不代表文稿合格！**
> 如果下一场活动是**手工实践**，敏感肌可能是“胶水打翻、材料损耗严重、成品粗劣”；如果是**情感恋爱团辅**，敏感肌可能是“前任八卦纠纷、表白被拒、隐私泄露”；如果是**体育竞赛**，敏感肌可能是“裁判争议、体能透支、赛后沮丧”；如果是**学术科创**，敏感肌可能是“组员甩锅、代码崩盘”。
> **不能让大模型因为量化词表全绿就万事大吉，必须在交付前启动独立的语义级、价值观级“苏格拉底追问式背靠背审查”！**

#### ① 审查执行方式

在自动化脚本体检通过后，主 Agent **必须启动一个独立的子 Agent/SubAgent（当且仅当 没有子代理工具时，才允许主会话中审核，且必须切换为严苛独立的“主审官”视角）**，执行以下背靠背对抗审查。

#### ② 苏格拉底独立主审官 Prompt 模板

```text
你现在是计算机学院党委宣传与文稿终审的“特邀独立主审官”。
你的任务是对眼前生成的《新闻稿》与《工作总结》进行最挑剔、最具政治敏锐度和公文修养的背靠背对抗性语义审查。
严禁浮于表面的客套赞美，严禁只看字数统计。你必须以“防通报、防舆情、防挨批、重体面”为唯一准绳，逐字进行以下【五大苏格拉底追问】：

【追问一：政治站位与向上向善（Civilization & Positivity）】
- 新闻稿代表学院官方门面面向全校展示。文稿的立意是否符合新时代文明之风？是否弘扬向上向善、蓬勃朝气的青年风貌？
- 全文是否存在任何丧气、宣泄抱怨、低俗或阴暗心理的描写？

【追问二：家丑不外扬与公文高阶雅化（Institutional Dignity & High-level Abstraction）】
- 针对本次活动的具体类型（手工/恋爱/体育/科创/人际），现场是否暴露了任何不体面的细节、生活琐屑、私人纠纷或操作失误？
- 是否做到了公文高阶雅化？（如：生活琐事摩擦是否雅化为“生活作息协调与公区秩序维护”；手工翻车是否雅化为“在反复调试中领悟工匠精神”；情感八卦是否雅化为“树立理性健康的交往观”）
- 有无直接将“市井大白话、寝室碎碎念”直接搬上公文版面的情况？

【追问三：内外有别与受众边界（Internal vs. External Audience Separation）】
- 对外新闻稿是否坚决做到了“内外隔离”？
- 新闻稿中是否绝对清零了：①内部问卷回收统计（如“回收11份问卷、X人觉得不满意”）；②内部工作分工与部员姓名；③活动筹备纰漏与后续改进措施？

【追问四：去杂音与共性提炼（Signal vs. Noise in Work Summary）】
- 工作总结的“不足与改进”中，是否混入了“仅1人提出的主观情绪吐槽、偏激要求或偶然个例”（如个人对某位同学发言的情绪评价）？
- 改进措施是否抓住了“流程、物资、时间、机制”等具有普遍整改价值的组织共性问题，而非给个案当传话筒？
- 工作总结篇幅是否严格受控在 800—2000 字区间？是否存在长篇大论、机械堆砌问卷明细或表格泛滥导致篇幅冗长失控？

【追问五：公文骨力与去 AI 浮夸（Pragmatic Tone & Discourse Purity）】
- 是否存在“不是……而是……”、“不仅是……更是……”等二分套话壳？
- 中间段落末尾是否出现无意义的强行升华口号？

【输出裁决要求】：
1. 总体裁决：【PASS 批准交付】 或 【REJECT 驳回重改】
2. 逐项追问审查意见（列出具体命中的句子与违规原因）
3. 具体修改指令：若驳回，给出每一处有问题的句子的“公文高阶雅化示范”，主 Agent 必须改写后再提交。
```

#### ③ 审查闭环机制

- 只有当独立主审官判定为 `【PASS 批准交付】` 时，流程才能流转至下一步（智能排版与原生 Word/XML 文件生成）。
- 一旦主审官判定为 `【REJECT 驳回重改】`，生成 Agent 必须根据雅化示范立即修正文稿，重新经过审查，形成可靠的质量闭环。

## 八、图片筛选与智能排版拼图规范

活动照片是体现活动质量、师资规格与育人实效的核心载体。AI 与归档人员协同选片、智能排版时，不锁死固定像素比例，由 AI 作为“视觉编导”根据实际照片构图、张数与文稿叙事节奏动态决策最优拼图方式。

### 1. 指导老师现场拍摄与选片红线要求（底线把关）

归档人员提供照片或 AI 协同筛选时，必须严格遵守以下 3 条红线：

1. **主讲/嘉宾特写必选**：抓拍讲解要点、示范动作、倾听互动等生动神态，彰显活动师资规格与指导深度；画面要清晰，杜绝闭眼、抓拍变形或背光过暗。
2. **全场照画面必须端正完整，严禁“半个头、半个人”**：拍摄全景和围圈全景时，画面水平线要正，构图平衡，**边缘严禁出现裁切半个身体或半个脑袋的不严谨构图**。
3. **整体全景与个别学生特写兼备**：大景深（全场围圈、破冰互动、大合影）展现现场整体参与感，小景深微距特写（学生举手发言、专注制作手部动作、真诚交流与微笑）展现沉浸感与真实反馈。

### 2. 两类稿件的选片原则与差异对照

| 维度               | 新闻稿（对外宣传）                                                                                                                       | 工作总结（对内复盘）                                                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| **选片定位** | **少而精**（视觉锚点，严选高光）                                                                                                   | **全而细**（工作证据链，过程复现）                                                                                                    |
| **选片数量** | 精选 3~4 组拼图或单张焦点大图                                                                                                            | 精选最多 10~20 张分类存档上报，正文视需插入少量                                                                                            |
| **选片内容** | • 必须有：主讲老师讲解/指导特写• 必须有：全场破冰/围圈端正大景深• 必须有：学生专注动手或小组热烈讨论• 必须有：成品展示或学生生动笑脸 | • 覆盖全流程：前期场地布置与签到台• 教学 PPT 课件内容与老师授课细节• 细致的物料、工具与制作分步记录• 问卷回收填写现场、场地清理收尾证据 |
| **视觉排版** | 强烈建议采用**多图并排拼图**，统一纵横比例，避免推文或排版时连续竖图造成视觉割裂                                                   | 可按章节附单张原图或按环节做缩略索引图，更注重原图细节与备查属性                                                                            |

### 3. 活动照片三级文件夹管理规范（实践路径）

依据真实工作实践，建立规范的三级目录：

- `1.精选照片/`：从海量生图中筛选出的高光代表照片，按环节规范重命名（如 `01_全场_老师引导大风吹.jpg`、`06_老师特写_讲解.jpg`、`09_分组讨论_老师参与.jpg`、`13_学生特写_发言.jpg`）。
- `2.拼图/`：根据新闻稿段落节点生成的标准排版拼图（如 `拼图1_全场大风吹.jpg`、`拼图2_分组讨论.jpg`、`拼图3_老师特写.jpg`、`拼图4_学生交流.jpg`）。
- `3.完整图片/`：现场拍摄的所有原始生图完整归档备份。

### 4. AI 智能拼图排版决策机制（不锁死比例，动态自适应）

拼图无需机械限制死板分辨率，由 AI 结合图片属性与段落叙事动态决策：

1. **单图大景（Hero Image，适合独立展示）**：
   - **适用**：大合影、大景深全场围圈全景、构图极佳的主讲老师半身特写。
   - **处理**：保持原片高清比例，居中单张排版，保留恢宏视觉冲击。
2. **横向双联（2-in-1 Side-by-Side）**：
   - **适用**：两张动作连贯、正反对比或呼应的图片（如“老师示范 + 学生操作”、“破冰大风吹双重视角”、“两位发言同学特写”）。
   - **处理**：自适应等高或等比居中裁切（如 4:3），中间保留 6~8px 纯白中缝，形成横版舒展视觉。
3. **横向三联（3-in-1 Sequence）**：
   - **适用**：三步连贯动作展示（讲解 → 示范 → 实践）或三个小组讨论画面的横向并列。
   - **处理**：三张竖版或方版等高并排，整齐紧凑。
4. **四宫格（2×2 Grid）**：
   - **适用**：多组手工艺品展示、多位同学微表情/作品特写、四个并行环节的矩阵概括。
   - **处理**：四图按 2×2 排列，统一留白中缝，形成整体模块感。

### 5. 自动化辅助拼图工具（仅作参考，可以按实际需要调整改进）

技能提供自动化拼图工具脚本 [scripts/stitch_photos.py](./scripts/stitch_photos.py)，支持智能等高自适应与多布局：

```bash

python3 scripts/stitch_photos.py <图片1> <图片2> -o <输出拼图路径>

# 4 张图自动拼成 2x2 宫格：

# 指定 4:3 比例裁切并保持指定高度（例如新闻稿标准横图）：

```

## 十、质量红线

1. **新闻稿字数硬线**：新闻稿正文纯汉字数严格控制在 **500—520 字**之间（容差区间 490—540 字，严禁突破 540 字，过程段限 1~2 段杜绝冗长）。
2. **事实求是**：不得虚构人数、作品数、问卷数据、领导姓名、奖项。
3. **内外有别**：新闻稿不得出现内部负责人姓名与问题不足。
4. **务实复盘**：工作总结不得只写成绩、回避问题，杜绝假大空套话。
5. **口径一致**：两稿时间、地点、人数、活动全称必须严格一致。
6. **缺失必标**：缺失信息一律标“【待补】”，不得用模糊语言糊弄掩盖。
7. **新闻稿去琐屑**：新闻稿严禁出现内部生活琐事（如泡面、刷碗、个人生活习惯摩擦）与问卷整改明细，必须升华为公文抽象语汇。
8. **工作总结去杂音**：工作总结严禁将仅 1 人提出的非共性主观抱怨或缺乏合理性的情绪吐槽直接立项为改进点。
9. **工作总结字数硬线**：工作总结正文纯汉字数严格控制在 **800—2000 字**之间，严禁突破 2000 字导致篇幅冗长失控，严禁低于 800 字导致复盘流于形式。
10. **成果交付 Word 化**：必须生成可供双击打开的 Word 成果文件（.docx/.xml），保障格式一次成型。

## 十二、学生骨干人工核验与防挨骂培训手册（How to Quality-Check）

> **给学生骨干的核心认知**：
> AI 是我们高效工作的“超级秘书”，但**最终文稿署的是学院与部门的名字，承担 100% 政治安全与真实性责任的是我们自己**。老师和学院批评从来不是因为“文笔不够华丽”，而是因为“事实搞错、名字打错、内外不分、数据打架”。用好本技能，核心在于掌握“三关六查”核验法，花 3~5 分钟守住底线，少给 AI 擦屁股，不返工、少挨骂。

### 1. 人工 vs AI 责任分工表

| 维度                 | AI 负责搞定（信任并交由 AI 执行）      | 同学必须人工负责（绝对不能盲信 AI，必须人工闭环）                                                |
| -------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **框架与结构** | 自动搭建 8 部分总结模板与 5 段式新闻稿 | 确认是否有活动特有的特殊流程遗漏（如颁奖、临时领导致辞）                                         |
| **文字润色**   | 扩写润色、去 AI 味套话、字数精简压缩   | **内外口径审查**：绝不能让负面细节（寝室琐事摩擦、手工翻车破损、情感八卦纠葛等）溜进对外稿 |
| **事实与数据** | 从提供的材料中提取数字与名单           | **数据真实性裁决**：策划预估 vs 现场签到 vs 问卷份数，裁定唯一真实口径                     |
| **格式与排版** | 套用 WordML/docx 模板生成合规文件      | 打开 Word 快速肉眼浏览：标题字号、首行缩进 2 字符、中缝无错位                                    |
| **政治与组织** | 规范用语生成                           | **政治纪律红线**：学院全称、指导老师/领导姓名、头衔称谓必须 100% 准确                      |

---

### 2. “三关六查”极速人工核验法（5 分钟终审流程）

#### 第一关：新闻稿“对外防暴雷”三查（防公关危机、防通报）

- [ ] **一查关键人与抬头**：
  - 学院名称全称是否准确？（如“计算机科学与技术学院”或“计算机学院”与发布平台规范一致）；
  - 主讲老师/领导姓名是否有同音字错别字？（如“张老师”误写为“章老师”，AI 语音转文字最容易错，必须人工核准）；
  - 是否有老师未经同意被写进新闻稿？（未确认者统称“心理素质教育中心专职咨询师”等职务表述）。
- [ ] **二查现场负面细节与公文雅化（家丑不外扬）**：
  - 新闻稿是面向全校和社会的门面，**绝对严禁**出现任何活动现场的具体琐碎指控或负面翻车（如寝室类写“泡面碗发臭/不刷碗”、情感类写“前任纠纷/八卦”、手工类写“材料损坏/胶水弄脏”、文体类写“裁判争议/对抗失误”），必须核验是否已抽象为符合新时代文明之风的正规公文语汇；
  - **绝不写问卷细项**：“回收了11份问卷、9人满意”这类内部指标绝不能放进对外新闻稿。
- [ ] **三查字数与图片**：
  - 正文 Word 字符数（不计空格）是否受控在 **500—520 字符**（纯汉字约 440—460 字，过程段占比严格 <= 30%）？（运行 `python3 scripts/word_count.py <文稿路径>` 一秒诊断分块比例与真实字数）；
  - 配图是否有老师特写？全场全景照边缘是否切断了半个头或半个人？

#### 第二关：工作总结“对内防挨批”三查（防避重就轻、防虚浮假大空）

- [ ] **四查【待补】清零与分工落实**：
  - 文中所有“【待补】”标记（负责人姓名、物资、场地）在提交给老师前，必须人工填补为真实部员姓名，**不能把带有【待补】字样的半成品直接交上去**；
  - 部门职责是否责任到人，严禁全篇通篇“工作人员”。
- [ ] **五查数据口径统一（防数据打架）**：
  - 核查：实际到场人数、问卷回收数、获奖或作品数。如果策划写 30 人、报名 30 人，但签到表只有 18 人，**工作总结必须明确写实到 18 人**，决不能让老师在报告里看到前后自相矛盾的数字。
- [ ] **六查问题与对策质量（防以偏概全、防假反思）**：
  - **防止把“个例杂音”当大问题**：如果问卷里只有 1 个人情绪化吐槽了一句，或者某个极个别特殊要求，**严禁将其升格为大问题**立项整改，避免误导后续办会；
  - **对策必须有实招**：不能写“未来将进一步提高宣传意识”等假大空话，必须有“多备15%材料”、“设置5分钟答卷时间”、“开场贴出路线图”等具体动作。

#### 第三关：交付产物终审

- [ ] **七查交付完整性**：
  - 文件夹中是否已生成 `.docx` 文件？双击打开，检查格式是否整洁、图注是否居中对齐，保证老师打开即用。
